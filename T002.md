# T002 — Atualizações da API (para o Frontend)

Documento com os endpoints novos/alterados nesta ronda, com payload completo.

---

## 1. Editar utilizador (endpoint novo)

**`PUT /auth/utilizadores/{utilizador_id}`** (Gestor)

Todos os campos são opcionais — só envia o que quer alterar:

```json
{
  "nome": "Maria Silva",
  "email": "maria@bisness.com",
  "password": "novaSenha123",
  "role": "GESTOR",
  "ativo": true
}
```

Response (mesmo formato de `GET /auth/me`):
```json
{
  "id": "9c4803db-19dc-40c1-9d84-bf47b1ae74fb",
  "nome": "Maria Silva",
  "email": "maria@bisness.com",
  "role": "GESTOR",
  "ativo": true
}
```

- 404 se o utilizador não existir
- 400 se o email já estiver em uso por outro utilizador
- 422 se a role for inválida (só aceita `OPERADOR`/`GESTOR`)
- Alterar a `password` não afeta nenhuma sessão já ativa (token JWT continua válido até expirar)

## 2. Valor final desejado na venda

**`POST /vendas`** ganhou `valor_final_desejado`: em vez de calcular a % de desconto manualmente, informa quanto o cliente quer pagar no final e o sistema calcula o desconto sozinho. Tem prioridade sobre `desconto_percentual` se os dois forem enviados.

```json
{
  "cliente_id": "af11fa27-2bbe-4834-acb3-4a249c0f5ce4",
  "itens": [{ "produto_id": "1edca05e-c4e7-490f-a90a-164a28ade8ad", "quantidade": 2 }],
  "valor_final_desejado": 5000.00
}
```

Response (total com IVA era 5700, cliente quis pagar 5000 — desconto calculado automaticamente):
```json
{
  "id": "2fc07e01-2e6c-4fea-b4b3-67c8b852bfc4",
  "total_sem_iva": 5000.0,
  "total_iva": 700.0,
  "total_com_iva": 5700.0,
  "desconto_percentual": 12.2807,
  "total_desconto": 700.0,
  "total_final": 5000.0,
  "credito": false,
  "credito_pago": false,
  "numero_factura": null
}
```

- Ambos os campos (`desconto_percentual` e `valor_final_desejado`) continuam **opcionais**. Sem nenhum dos dois, aplica o desconto automático de fidelidade do cliente (Bronze/Prata/Ouro), como já era antes.
- Se `valor_final_desejado` for maior ou igual ao total com IVA, não gera desconto negativo — fica `desconto_percentual: 0` e `total_final` = `total_com_iva`.
- `numero_factura` só vem preenchido quando `credito: true` (número da dívida gerada); `null` em vendas à vista.

Migrações: nenhuma (mudanças só de código/API, sem alteração de banco de dados).
